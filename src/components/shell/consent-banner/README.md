# ConsentBanner

## 用途

任意の用途に cookie を使ってよいかを、利用者が選び終えるまで尋ね続ける面です。画面の下端に張り付き、背面を覆います。

## 役割と公開 component

| Component | 役割 |
| --- | --- |
| `ConsentBanner` | 尋ねる面を描き、選ばれた意思を `onDecide` で呼び出し元へ返します。状態も保存も持ちません。 |

文言は `consent-banner.definition.ts` の `CONSENT_BANNER_COPY` が owner です。同意状態の型・判定・cookie の綴りは [`model/consent.ts`](../../../model/consent.ts) が持ちます。

## 利用ケース

器へ一度だけ置きます。置くのは root layout で、尋ねているかどうかの判定と、選ばれた意思の保存は供給側（[0031](../../../../docs/adr/0031-policy-state-supply.md)）が持ちます。

**この部品は同意状態を読みません。** `open` を渡された通りに描くだけなので、Storybook でも、まだ選んでいない利用者の画面でも同じ振る舞いになります。

## 設計

- **閉じる手段を置きません。** Escape も、面の外を押す操作も、右上の × も受け付けません。選ばずに閉じられると「尋ねたが選ばれていない」状態が残り、次の描画でまた出ます。閉じる操作は選ぶことだけです
- **背面を操作させません。** 選び終えるまで focus は面の中を回り、支援技術からも背面が読めなくなります。焦点だけを閉じ込めて見た目の背面を開けておくと、見えている人と読み上げる人で操作できる範囲が食い違います
- **2 つの選択肢を同じ大きさで並べます。** 拒否だけを小さく・目立たなくすると、得られた同意が自由に与えられたものではなくなります
- **履歴を動かしません。** `Dialog` は戻る操作で閉じられるよう履歴を積みますが、この面は利用者が開いたものではないため、戻る操作の対象になりません
- **client island です。** focus の閉じ込めと背面の inert 化をブラウザ側で行うため hydration が要ります

## 隣の部品との使い分け

`Dialog` は利用者が trigger を押して開き、閉じる手段と戻る操作を持つ面です。この部品はどちらも持ちません。

## 確認範囲

- Storybook `Overlay/ConsentBanner` — 導線を添えた既定と、示す文書が無い場合
- テスト — 選択が `onDecide` へ渡ること、閉じる手段が働かないこと、`open` が偽のとき面が DOM に無いこと
