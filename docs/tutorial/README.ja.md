# チュートリアル

**実際に動くものを、レイヤーを順に上りながら組み立てる手順書**を置く。規約（[`rules.md`](../rules.ja.md)）と
判断（[`adr/`](../adr/)）と主題ごとの設計解説（[`design/`](../design/README.ja.md)）は「何が正しいか」を
持つが、「で、実際にどう書くのか」は持たない。ここはその 1 本の道筋を持つ。

## なぜここに要るか

このリポジトリの同梱サンプルは、テンプレートから作った側が最初に破棄する。そのとき実装の実例が
まるごと消え、残るのは規約と ADR とレイヤー別 README だけになる。**ここにある文書は、破棄のあとにこそ
読まれる**——だから消える側のコード（題材の feature と、それに固有の adapter・route・仕様書）を
参照せず、消したあとの状態から始める。

## 文書

| 文書 | 何を作るか | 通すレイヤー |
| --- | --- | --- |
| [build-a-screen.md](build-a-screen.ja.md) | 1 つの画面（一覧・詳細・1 件の編集）を契約から表示・送信・テスト・カタログまで | `openapi/` → `model` → `adapters/server` → `features` → `app` → 送信 → テスト → カタログ → 仕様書 |

## 読み方

- 各 Step は **目的・触るファイル・実物のコード・迷う分岐の行き先・確認コマンド** を持つ。判断の
  中身はコピーせず、判断を持つ文書（ADR / レイヤーの README / `design/`）を名指しする。コピーは腐る
- 依存の順（契約 → 内側のレイヤー → 外側のレイヤー）で並べてある。**画面を作るときの作業順は別**で、
  [`playbook.md`](../playbook.ja.md)「画面を作るときの順序」が持つ
- 載せている検査コマンドは、書いたファイルだけを回すものに限る。全体のゲートは hook と CI が回す
  （[0151](../adr/0151-git-hooks.ja.md)）

## ここに置かないもの

| 置き場 | 何を持つか |
| --- | --- |
| [`get-started/`](../get-started/) | テンプレートからリポジトリを作る**最初の 1 回**の手順。以降は使わない |
| [`playbook.md`](../playbook.ja.md) | やりたいことから置き場を引く逆引きと、画面を作るときの作業順 |
| [`design/`](../design/README.ja.md) | 主題ごとの設計解説。レイヤーを跨ぐ 1 つの主題を通しで説明する |

チュートリアルは**通しの実例**であって、逆引きでも解説でもない。同じ主題を 2 か所で説明したく
なったら、解説は `design/` へ置き、ここからはリンクだけを張る。
