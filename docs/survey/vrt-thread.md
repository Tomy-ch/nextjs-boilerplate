# 調査台帳: a11y の worker 数

> **このファイルはこのブランチだけのものである。マージ前に削除する。**
> `.claude/settings.json` の `SessionStart` hook も併せて落とす。撤去は
> [PR のチェックリスト](#撤去)が持つ。

複数日にまたがる測定なので、セッションをまたいで記録が消えないようここへ積む。

## 何を確かめたいか

`a11y` の worker 数を**コア数より多く**すると実行時間が縮むか。

前提は、以前 `--workers=4`（= public runner のコア数）を入れたときに**効果が測定できなかった**こと。
効かなかったのではなく、ランナー個体差（±40%）に埋もれて判定できなかった。そのとき速かった実行は
むしろ flaky を 8〜11 件抱えており、仕事量が多い側が速いという逆転すら起きている。

コア数まで増やして変わらないなら、ループは CPU で飽和していない可能性がある。待ち（ページ読み込み・
フォント・安定化）が支配的なら、コア数を超えて worker を積むと素直に伸びるはずである。

## 測り方

**`vrt` を対照に使う。** 同じ push で同じランナー世代の 2 ジョブが走るので、`vrt` の実行時間が
そのランナーの速さを表す。比 `a11y / vrt` を見れば個体差が相殺される。

- **処置**: `a11y` = `--workers=200%`
- **対照**: `vrt` = 変更しない（Playwright 既定 = コア数の半分）

判定は比の変化で行い、`a11y` の絶対値では行わない。

### 基準値（変更前）

| run | a11y | vrt | 比 | 備考 |
| --- | --- | --- | --- | --- |
| 31790809046 / 31790809141 | 611 tests / 7.0m | 646 tests / 4.2m | **1.67** | テーマ 1 本化の直後 |

## 記録

各実行で次を書く。worker 数は `Running N tests using M workers` の行から取る（tee により CI の
ジョブログに出る）。

| 日付 | run (a11y / vrt) | worker 数 | a11y | vrt | 比 | flaky | メモ |
| --- | --- | --- | --- | --- | --- | --- | --- |
| | | | | | | | |

## 判定の条件

- **採用**: 比が基準の 1.67 から**有意に下がる**。サンプルは最低 5 対。1 対だけの改善では判定しない
- **棄却**: 比が変わらない、または flaky が増える。オーバーサブスクリプションはメモリ競合で
  `Axe is already running` の衝突窓を広げうるので、**flaky 件数も必ず記録する**
- どちらでも、結論を PR 本文へ書いてから撤去する

## 撤去

判定が出たら、採用・棄却のどちらでも次を行う。

1. `docs/survey/vrt-thread.md`（このファイル）を削除
2. `.claude/settings.json` の `hooks` を削除
3. 結論を PR 本文へ残す（台帳の表もそこへ写す）

棄却なら `a11y.yaml` の変更も戻す。採用なら `--workers=200%` だけが残る。
