# `/mypage/edit` プロフィール編集

登録情報を書き換える画面。マイページとは独立したルート。

## 見せるもの

9 項目を 3 節に分ける。

| 節 | 項目 |
| --- | --- |
| 基本情報 | 姓・名（横並び） |
| 連絡先 | メールアドレス・電話番号 |
| 住所 | 郵便番号（`[住所を検索]` 同梱）・都道府県・市区町村・丁目番地・建物名 |

建物名だけが任意。**必須・任意の印は検証スキーマから導く**（`isRequiredProfileField()`）。
列挙すると、規則を緩めたのに画面が必須のままという状態を作れる。

印は label の前に置く。「必須」「任意」がどちらも 2 文字なので、印の列と label の開始位置が
同時に揃う。印は `aria-hidden` で、必須であることは control の `aria-required` が伝える。

## CollectAll

「自分の情報」と「都道府県マスタ」を RSC 内の `Promise.all` で並置合成する。

```text
GET /v1/users/me    ┐
                    ├─ 並置するだけ（ドメインの計算を挟まない）
GET /v1/prefectures ┘
```

**合成をバックエンドへ寄せない。** 片方の結果がもう片方の取得条件にならず、計算も要らないため、
フロント側で並べれば足りる。寄せると画面の都合で契約が 1 本増える
（[screens.md](../../../screens.md) §1）。

都道府県は `SelectNative`。契約が全 47 件を固定で返す静的な候補なので、client island の検索 UI を
持ち込む理由がない。

## 検証

**誤りを出すのは focus が外れた時点。focus が当たっている間は、表示を消す方向にだけ効かせる**
（reward early, punish late。[0062](../../../adr/0062-form-input-validation.md)）。

| 操作 | 表示 |
| --- | --- |
| 正常な値の項目を focus 中に空にする | 出さない |
| focus を外す | 出す |
| focus して直す | **その場で消す** |
| focus 中にまた壊す | focus した時点と同じ文言のまま |

実装で 2 つ必要になる。rhf の `reValidateMode` は **submit のあとにしか効かない**ため `mode` を
`onTouched` にすること、そのうえで focus 中の表示を「焦点を当てた時点の文言」で頭打ちにすること。
後者が無いと、書き直そうとして 1 文字消しただけで「入力してください」が現れる。

検証は client と server の両方で同じ表示検証スキーマ（`model/user/profile-schema.ts`、手書き）を
通す。client 側は即時に返すためのもので、通ったことは保証にならない。契約に照らした検証は
`adapters` の境界が生成スキーマで別に行う。

## 住所補完

郵便番号から focus が外れた時点と、`[住所を検索]` を押した時点に走る。

```text
入力欄 → /api/addresses（Route Handler）→ adapters/server → GET /v1/addresses
```

- **候補が割れた項目は埋めない。** 1 つの郵便番号が複数の町域を指すことがあり、先頭を無条件に
  採ると利用者が選んでいない住所が黙って入る
- **町域を入れるのは丁目・番地が空のときだけ。** 番地は補完に含まれないので、上書きすると
  利用者が書いた番地が消える
- **引けなくても先へ進める。** 契約は外部 lookup の障害を `503` ではなく空の候補で返すため、
  画面は「見つからなかった」と同じ扱いで手入力を続けさせる
- **同じ郵便番号は 2 度引かない。** 値を変えずに項目を通り過ぎただけで要求が出る。ただし
  **操作で呼ばれたときは引き直す** —— 押した操作が何も起こさないと壊れていると読まれる
- 補完が起きたことを読み上げる。入力欄の値が変わるだけでは、そこを見ていない利用者に届かない。
  待機中の文言は持たない（応答が速いと結果と入れ替わって戻り、文字が明滅する）

## 送信

`<form action>` + `useActionState` + `useFormStatus`（[0061](../../../adr/0061-form-mutation-ux.md)）。
rhf は入力中の検証だけを持ち、送信機構を置き換えない。JavaScript が動かない環境でも form は
そのまま送信され、server 側が同じスキーマで検証する。

成功しても画面を移さず、toast で伝える。フォームの文脈に留まる保存であるため
（[0063](../../../adr/0063-mutation-result-notification.md)）。マイページ側は次に開いたときに
新しい内容が出るよう、Server Action が再検証を要求する。

**更新の対象を指す識別子を画面へ渡さない。** `adapters` の中で解決する。フォームの hidden に
載せると、ブラウザに置く理由の無い値が出る。

## 認可

マイページと同じ（proxy の楽観判定 + `verifySession()` の確定認可）。

## パンくず

`マイページ > プロフィール編集` を置く。global nav から 1 手で戻れない祖先を持つため
（[0026](../../../adr/0026-layout-shell-mount.md)）。
