# `/admin` 外枠（画面要件）

> 機能要件は [`layout.function.md`](layout.function.ja.md)。

管理画面の外枠。利用者向けの外枠とは**別のレイアウトシェル**で、導線を横ではなく脇に置く。

## なぜ 1 枚にしないか

見せる相手が違い、導線の数と深さも違う。1 枚にまとめると、相手で導線を差し替える分岐をレイアウトシェルの中に
抱える（[0026](../../../adr/0026-layout-shell-mount.ja.md)）。管理の操作は対象（商品・利用者・集計）
ごとに増え、増える方向が縦なので横並びの header には収まらない。

## 見せるもの

| 区画 | 内容 |
| --- | --- |
| サイドバーの一覧 | 管理側の名称と、対象ごとにまとまった導線 |
| header | サイドバーの一覧の開閉・サイト名・利用者向け画面へ戻る導線 |
| 現在地までの階層 | 本文の先頭。中身は各画面が渡す |
| 本文 | 各画面の中身。幅は絞らない |

**3 つの名前が別の場所を指す。** サイドバーの先頭の「管理」は管理のホーム、header のサイト名はサイトの
トップ、「ユーザー画面へ」は利用者向けの主画面。同じバーに同じ行き先を 2 つ置かない。

**現在地までの階層は、位置だけをレイアウトシェルが持つ。** 画面ごとに置くと、同じものが画面ごとに違う高さへ
現れる。左端は本文と揃える —— ずれると、現在地が本文の外側の飾りに見える。**渡された中身が空の
ときは場所ごと詰める** —— 階層を持たない画面が上端に空白を抱えないようにする。

**画面を出せなかったときも、見つからなかったときも、レイアウトシェルの中に出す。** サイドバーの一覧と header は残り、
見つからない面は管理のホームへ戻る導線を 1 本持つ。レイアウトシェルごと外すと、管理の中での現在地と次の行き先を
一度に失う。

## サイドバーの一覧

**導線は対象でまとめ、まとまりには見出しを付ける。** 見出しは押しても遷移しない —— 遷移させると、
見出しと直下の先頭項目のどちらを押せばよいかを毎回確かめることになる
（[0053](../../../adr/0053-ui-component-interaction-seam.ja.md)）。

**まとまりは畳める。** 開閉は `details` / `summary` の native の機構に乗せる。開閉のためだけに
browser の状態を持つと、最初のレンダリングで全部開いた姿が一度出る。

**いま開いている画面にマーカーを付ける。** マーカーが付くのは行き先が今いる場所と**完全に一致する**ときだけ。
前方一致にすると、下に画面を足した時点で一覧と作成の両方にマーカーが付く。

## 幅で変わるもの

| 幅 | サイドバーの一覧 | header の操作 |
| --- | --- | --- |
| 脇に置ける | 常設。畳める | 畳む操作 |
| 置けない | overlay へ畳む | 開く操作 |

**出す導線は幅によらず同じ。** 幅で顔ぶれを変えると、狭い画面でだけ辿り着けない場所ができる。

**畳む操作と開く操作は別のコンポーネントにする。** 同じ位置にある操作の結果が幅によって変わらないように
するため。バンドの境界は [0051](../../../adr/0051-styling-system.ja.md) が持つ。

**畳んだ状態は覚えない。** 覚える先は cookie になり、レイアウトシェルのためだけに要求ごとの読み取りを増やす
ことになる。画面を移っても続くのは、遷移でレイアウトシェルが作り直されないため。

## レイアウトシェルが持たないもの

**本文の幅を絞らない。** 読み幅と左右余白は本文の側の責務で、両方が幅を持つと画面ごとにどちらが
効いているのかを読まないと分からなくなる。

**header の右に出すものと、サイドバーの下端に出すものの中身を知らない。** 置き場所だけを用意する。
利用者向け画面へ戻る導線もその 1 つで、レイアウトシェルは行き先を持たない。

**紙には出さない。** header・サイドバーの一覧・skip link はいずれも画面を渡り歩くためのもので、紙の上では
押せず場所を取るだけである。
