# `/admin/products/[id]/discontinue` 商品の廃番（機能要件）

> 画面要件は [`page.screen.md`](page.screen.ja.md)。
>
> 認可・レイアウトシェルの約束は [`../../../layout.function.md`](../../../layout.function.ja.md) が持つ。

1 つの商品を廃番にしたときに何が影響を受けるかを示し、代替クーポンの条件を受け取って廃番にする。
廃番は取り消せず、この画面はそこから戻る道を差し出さない。

## 主体と所有

**admin の役割が要る。** 画面に届くかどうかは外枠が決める。

**結果を決めるものはすべてバックエンドが持つ** —— どのカートに商品が入っているか、誰がクーポンを
受け取るか、進行中の購入が廃番を止めるか、どの条件を受け付けるか。この画面は条件を組み、送り、返って
きたものを出すだけ（[0070](../../../../../../adr/0070-backend-role-separation.ja.md)）。

## 商品は未公開を含めて読む

**商品は未公開の商品を含む母集団から読む。** 廃番の商品は非公開になるため、公開済みだけを読むと、
廃番にした瞬間と、既に廃番のすべての商品で、この画面が not-found になる。存在しない識別子は not-found。

## 取得

| 何を | いつ | 失敗したら |
| --- | --- | --- |
| 商品 | 常に | 画面全体 |
| 見積もり | 商品がまだ廃番でないときだけ | 画面全体 |
| 進行中の購入 | 見積もりが 1 件以上を数えたときだけ | その領域だけ。見積もりは残る |

**既に廃番の商品には見積もりを取らない。** もう一度廃番にしても何も変わらず 0 が報告されるので、
見積もるものも差し出すものも無い。

**見積もりはその時点の写しであって、約束ではない。** 何もロックせずに読み、返った時点から古くなる。
鮮度の断りと読み直す導線を添え、**結果として出すことは無い** —— 実際に起きたことは実行の応答だけが持つ。

**進行中の購入は別に取得し、別に失敗する。** これが答えるのは「何が止めているか」で、見積もりより
従の情報になる。読めなくても見積もりは失わない
（[0080](../../../../../../adr/0080-error-handling.ja.md)）。

## 3 つの立ち位置

| 立ち位置 | 出すもの | 実行 |
| --- | --- | --- |
| 廃番にできる（見積もりが進行中の購入を数えない） | 見積もりとクーポンの条件 | 差し出す |
| 進行中の購入が残っている | 見積もりとその購入 | 差し出さない |
| 既に廃番 | いつ廃番になったか | 差し出さない |

**進行中の購入が残っている間は、実行を差し出さない。** 1 件でも残っていれば契約は廃番を拒むので、
拒まれると判っている操作を置かない。代わりに出すのはその購入で、それを終わらせることが廃番を可能に
するから。

**「empty」はどのカートにも入っていない状態** —— 3 つの数がすべて 0。実行は差し出し、単にクーポンが
発行されない。

**3 つの立ち位置は、送ったものを捨てずに切り替わる。** 送信の後に画面は取り直され、行き着く立ち位置が
出発したときと違うことがある。送信の結果はその切り替えをまたいで残る。

## 進行中の購入

**母集団は見積もりと同じ —— この商品を含み、完了・キャンセル・配達済みのいずれでもない、全ユーザーの
購入。** 見積もりの件数と隣に並ぶ行は同じ母集団から来なければ、2 つの数が食い違って読める。絞り込みは
条件としてバックエンドへ送り、受け取った行を画面で絞らない。

**並べるのは 20 件までで、ページ送りは無い。** それより多いとき、または見積もりが数えたより少なく
並んだとき（見積もりの後に入った購入や、画面が知らない状態）は、全件ではないと書く。

**行はどこへもつながらない。** 管理側には購入 1 件を開く画面が無く、押しても何も起きない行を link と
して差し出さない。

## クーポンの条件

**2 つの条件は空で始まり、どちらも必須。** どれだけを、どれだけの期間補償するかは業務の判断で、前もって
入れた値は誰かが選んだ値と見分けがつかない。

**値引き率は百分率で打たせ**（`10` で 10% 引き）、**契約の乗数である decimal 文字列で送る。** 画面は
小数点を文字列のまま 2 桁ずらし、数へは変換しない
（[`docs/rules.md`](../../../../../../rules.ja.md#formatting): decimal は文字列で持ち回る）。その前に、
契約が宣言する形に照らす。空白・符号・指数・全角数字・`%` は読めない。桁数は制限しない。

**率の範囲（0 より大きく 1 以下）は画面で照らさない。** 契約がそれを散文でしか述べていないため、
画面は `0` も 100 を超える値も送り、拒否がその欄へ戻ってくる。

**有効日数は、契約が宣言する範囲の整数日で、** 画面はその宣言に照らす。画面独自の上限は足さない。

**読めない条件は確認を開かせない。** 理由は欄ごとに出す。

## 確認

**廃番は確認の中からだけ送る。** 送信は確認を通った合図を載せ、送信先は合図の無い送信を断る ——
送信先はこの画面を経ずに呼べる。商品・冪等キー・合図のいずれかが欠けた送信には、画面を開き直して
もらうよう答える。どれも、その場でユーザーが直せるものではない。

## 送信

**送るのは 2 つの条件と冪等キー。** キーは画面を組み立てるたびに 1 つ作り、画面が mount されている間は
持ち続けるので、送り直しは最初の送信へ畳まれる。

**成功したら、この画面に留まる。** 実行が何をしたかの件数 —— 理由が出るようになったカート、クーポンを
受け取ったユーザー、発行したクーポン —— はその応答にしか無い。契約に読み直す口は無く、もう一度実行すると
0 が報告される。別の画面へ移るとそれを失う。画面は取り直され、商品を廃番として示し、その上に応答を出す。

**これが「成功したら別の URL へ移る」（[`docs/rules.md`](../../../../../../rules.ja.md#forms)）から外れるのは、
再読み込みで失うものの点だけ。** 完了そのものは消えない。再読み込みしても、いつ廃番になったかは出る。
消えるのは件数だけで、画面はそう書く。

## 失敗

| 何が起きたか | 扱い |
| --- | --- |
| 見積もりの後に進行中の購入が現れた（409） | この画面でしか言えない文言。画面が取り直されるので、最新の見積もりと、まだ残っていれば進行中の購入が出る |
| バックエンドが拒んだ条件を名指しした（422） | その欄に出す。この画面に無い項目しか名指ししない拒否は、汎用の文言になる |
| 条件が読めない | 確認を開く前に止める |
| 商品・キー・確認の合図が欠けている | 画面を開き直してもらう |
| 一時的に受け付けられない、またはその他の失敗 | その分類に対するカタログの文言 |
| 進行中の購入を読めない | その領域だけがそう書き、読み直す導線を添える |
| 役割が足りない | レイアウトシェルが入口で止めるため、この画面には現れない |
