# `/admin/products/[id]/discontinue` 商品の廃番（画面要件）

> 機能要件は [`page.function.md`](page.function.ja.md)。
>
> レイアウトシェルの約束は [`../../../layout.screen.md`](../../../layout.screen.ja.md) が持つ。

1 つの商品を廃番にしたときに何が影響を受けるかを見て、廃番にするかを決める画面。

## 見せるもの

上から次の順に並べる。

| 領域 | 中身 | いつ |
| --- | --- | --- |
| 見出し | 画面の名前と、廃番は取り消せないこと | 常に |
| 結果 | 実行が何をしたか | 実行が成功した直後だけ |
| 見積もり | 3 つの数・その鮮度・読み直す導線 | 商品が廃番でない間 |
| 既に廃番 | 商品がいつ廃番になったかと、一覧へ戻る link | 商品が廃番のとき |
| 拒否の理由 | 直前の実行が進行中の購入のために断られた理由 | その拒否の直後だけ |
| 進行中の購入 | 廃番を止めている購入 | 見積もりが 1 件以上を数えている間 |
| 条件と実行 | クーポンの条件・「廃番にする」・「キャンセル」 | 見積もりが 1 件も数えていない間 |

**並びは判断の順に従う。** 何が起きたか、何が起きるか、何が妨げているか、何を決めるか。結果が先頭に
あるのはそれが最も新しい事実だからで、拒否の理由はそれが指す購入の真上に置く。

## 見積もり

**3 つの数を同じ段に並べ、それぞれに数えている母集団の注記を添える。** 商品が入っているカートは持ち主の
決まっていないカートを含み、クーポンを受け取るユーザーは持ち主の決まっていないカートと退会したユーザーを
含まない。進行中の購入は 1 件で廃番を止めるのに足りる。並んだ数は、断りが無ければ同じ母集団から来た
ものとして読まれる。

**数は読み込んだ時点の値で、結果と一致しないことがあると書く。** 読み直す導線は常に出しておく。

**3 つの数がすべて 0 のときは、どのカートにも入っておらずクーポンは発行されないと書く。** 0 の並びだけ
では、実行が何かをするのかが判らない。

## 進行中の購入

**何が廃番を止めていて、何で終わるかを書く。** 購入がそれぞれ完了・キャンセル・配達済みのいずれかに
なれば廃番にできる。

**各行は購入コード・状態名・注文日時・合計を出す。** 行は link にしない。

**全件を並べていないときは、何件出しているかと、ほかにもあることを書く。**

**読み込みの間は、見積もりを出したまま、仮の行がその場所を埋める。** 読めなかったときはその領域が
そう書き、画面を読み直す導線を添える。見積もりは残る。

## クーポンの条件

**値引き率と有効日数の 2 つの欄で、値は入れておかない。**

**値引き率は百分率であることをラベルに書き、`10` で 10% 引きになるという補足を添える。** 欄は小数の
キーパッドを開くテキストの欄で、数値型の入力ではない —— 数値型の入力は値を数として持ち回る。

**有効日数には、発行した日から数えることと、契約が認める最長の日数を補足に添える。**

**誤りは確認を開こうとしたときに各欄の隣に出し、欄を離れたときには出さない。** 打ちかけの欄を離れる
のは誤りではない。**条件を変えると、前の文言は消える。**

## 実行とキャンセル

**「廃番にする」は破壊的な見た目を持ち、送信はしない —— 確認を開く。** 「キャンセル」はその隣に置き、
一覧へ戻る。影響を見てやめると決める経路のため。

## 確認

**題に商品を名指しする。** 商品名はダイアログを横へ広げず折り返す。

**本文に書くのは:** 取り消せないこと、商品が非公開になり買えなくなること、既にカートにある明細は残り、
買えない理由が出ること、見積もりの時点で何人のユーザーがクーポンを受け取るかと、打ったままの率と有効日数。

**選択肢は「やめる」と「廃番にする」で、後者は破壊的な見た目を持つ。** 背景を押しても閉じない。

**「廃番にする」を押しても閉じない。** 送信の間はボタンがそれを示し、もう一度は押せない。

| 結果 | 確認 | 文言が出る場所 |
| --- | --- | --- |
| 成功 | 閉じる | 画面の先頭の結果 |
| 進行中の購入が現れて断られた | 閉じる | 進行中の購入の真上 |
| バックエンドが条件を拒んだ | 開いたまま | 確認の中と、名指しされた欄 |
| その他の失敗 | 開いたまま | 確認の中 |

**進行中の購入による拒否で確認を閉じる**のは、画面が読み直されて実行がもう差し出されないため。開いた
ままにすると、もう存在しない操作の上に文言が浮く。ほかの失敗では開いたままにし、ユーザーが見ている場所に
文言を出す。

## 結果

**画面の先頭、確認の外に出す:** いつ廃番になったか、理由が出るようになったカートの数、クーポンを
受け取ったユーザーの数、発行したクーポンの数。

**件数はこの応答にしか無く、再読み込みすると日時だけが残ると書く。** その下では、画面は既に商品を
廃番として示している。

## 既に廃番

**商品が廃番であることといつからかだけを出し、一覧へ戻る link を添える。** 見積もりも、条件も、
実行も出さない。

## 待機

**待機表示は見積もりの枠と、その下の領域の高さを示し、どの立ち位置が続くかは約束しない。** 条件が
出るか購入が出るかは、見積もりが届くまで判らない。

## 失敗の見え方

**商品か見積もりが読めないときは、レイアウトシェルを残して本文だけを差し替える。** 進行中の購入だけが
読めないときは、その領域だけがそう書く。

## バンドによる違い

**3 つの数は `sm` 以上で横に並び、それ未満では縦に積む。** 2 つの条件の欄も同じ。進行中の購入の行は、
狭いバンドでは日時と合計をコードと状態の下へ折り返す。

## パンくず

**商品一覧管理 > 商品名 > 廃番。**

## カタログでの確認

Storybook の `Page/Admin/Products/Discontinue` に、廃番にできる状態（タブレットとスマートフォンを含む）・
