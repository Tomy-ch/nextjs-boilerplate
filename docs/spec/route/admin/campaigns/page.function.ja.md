# `/admin/campaigns` キャンペーン一覧（機能要件）

> 画面要件は [`page.screen.md`](page.screen.ja.md)。
>
> 認可・レイアウトシェルの約束は [`../layout.function.md`](../layout.function.ja.md) が持つ。

各キャンペーンの配布がどうなっているかを見渡し、配布を止める。

## 主体と所有

**admin の役割が要る。** 画面に届くかどうかは外枠が決める。

**コードを受け取れるかどうかはバックエンドが持つ。** この画面は契約が返す期間・件数・停止を読み、停止を
送る。クーポンを配ることも、誰が受け取れるかを決めることもしない
（[0070](../../../../adr/0070-backend-role-separation.ja.md)）。

## 何を並べるか

**すべてのキャンペーンを、配布開始の新しい順に並べる。停止済みのものも、期間を過ぎたものも含む。** 並び順は
契約のもので、画面は受け取った行を並べ替えない。

## ページ送りは位置で数える

**契約がページ番号とページの件数を受け取り、全件数を返すため、任意のページへ跳べる。** ページ数も、
そのページの位置も返さない。

**何ページあるかは全件数から導く。**

**1 ページの件数は画面が決める。** 契約が受け付ける上限は「これ以上は拒む」という線であって、何件
並べると読めるかとは別の理由で動く。

**URL に載るのはページ番号だけ。** 契約は絞り込みを持たない。

**URL は利用者が直接編集できる。** 読めないページ番号や、契約の上限を超えるページ番号は先頭のページへ
倒す。倒した結果はページ送りに現在のページとして見えるので、倒してよい側である。

**デフォルトの値は URL に載せない。** 同じ一覧に 2 つの住所ができる。

## 4 つの状態

**契約は状態を返さない。** 返すのは配布期間の両端と停止された日時で、行がどの状態にあるかは、それらを
「今」に当てて決める。

| 状態 | いつ |
| --- | --- |
| 「停止」 | 停止の日時がある。「今」が期間のどこにあっても |
| 「配布前」 | 「今」が開始より前 |
| 「配布中」 | 「今」が開始以降で、終了より前 |
| 「期間外」 | 「今」が終了以降 |

**停止は期間より先に見る。** 取り消せず、期間によらず配布を止める。

**期間は開始を含み、終了を含まない**（契約）。終了の時刻ちょうどでは期間外である。

**「今」はリクエストの時刻で、サーバーで読む。** 画面を開いたままにしても行の状態は進まず、一覧を
取り直したときに決め直される。

**配り切ったキャンペーンは独立した状態ではない。** 配布が終わるのは期間・停止・総数の上限への到達の
いずれかによるが、状態になるのは前の 2 つだけで、上限への到達は残数に出す。

## この画面が状態に色を割り当てる

**色は扱いの区分に付ける。** 商品一覧と同じやり方である
（[`../products/page.function.md`](../products/page.function.ja.md)）。

| 状態 | 区分 | 見た目 |
| --- | --- | --- |
| 「配布中」 | 受け取れる | 塗り |
| 「配布前」 | 待ちを伴う | 注意の色 |
| 「期間外」 | 済んだもの | 枠線だけ |
| 「停止」 | 確定した、取り消せない扱い | 明度の反転 |

**停止はほかと別の軸で見分けさせる。** 商品一覧での廃番と同じである。期間を過ぎたのは普通の終わりで、
停止は誰かが下し、取り消せない判断である。

## 残数

**残数は総数の上限から発行済みの数を引いたもの。** 契約はこの差で読むことを委ねている。発行済みの数は
クーポンが未使用に戻っても減らないため、残数も戻らない。

**残数が負になることは起きない。** 同時に受け取られても総数の上限を超えないと契約が宣言しているため、
画面はそれに備えない。

## 停止は不可逆

**確認を挟む。** 押し間違いが取り返せない。

**配ったクーポンは無効にならない**（契約）。停止が止めるのは配布であって、配ったクーポンではない。
画面はそれを停止の前にも後にも伝える —— 伝えないと、停止はもう配ったものを取り上げることだと読まれる。

**停止は停止済みの行を除くすべての行に差し出す** —— 配布前・配布中・期間外のどれでも。契約が拒むのは
停止済みのキャンペーンの停止だけで、まだ始まっていないキャンペーンは始まる前に止められる。契約が
受け付けるリクエストを画面は止めない。停止済みの行には何も差し出さない。もう一度実行しても何も変わらない
ためである。

## 送信

**送るのは対象のキャンペーンと、idempotency key。** 結果がどの行の話かを名指せるよう、コードも添える。

**キーは行の停止が選ばれるたびに作る。** 画面が多くの対象に操作を差し出すためである
（[`docs/rules.md`](../../../../rules.ja.md#forms)）。同じ送信の再送は同じキーを持ち、初回に畳まれる。

**成功したらこの画面に留まり、一覧を取り直す。** 停止はすぐに反映されるため、取り直した一覧ではその行が
停止済みとして出る。結果は一覧そのものの中で読むので、移る先の画面は無い。

## 失敗

| 起きたこと | 扱い |
| --- | --- |
| 既に停止済み、または同じ送信がまだ進行中（409） | ステータスだけでは 2 つを見分けられず、どちらにも同じように応じる。この画面だけが出す文言と、行が本当の状態に落ち着くよう一覧の取り直し |
| 対象かキーが送られてこなかった | 画面を開き直すものとして扱う |
| 一時的に受け付けられない、またはその他の失敗 | その区分に対するカタログの文言 |
| 一覧を取得できない | メインコンテンツだけを差し替え、レイアウトシェルは残す（[0080](../../../../adr/0080-error-handling.ja.md)） |
| 役割が足りない | レイアウトシェルがエントリポイントで止めるため、この画面には現れない |
