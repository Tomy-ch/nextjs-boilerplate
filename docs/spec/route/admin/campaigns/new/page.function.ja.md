# `/admin/campaigns/new` キャンペーンの定義（機能要件）

> 画面要件は [`page.screen.md`](page.screen.ja.md)。
>
> 認可とレイアウトシェルの約束は [`../../layout.function.md`](../../layout.function.ja.md) が持つ。

キャンペーンを 1 つ定義する。利用者がクーポンを受け取るために打つコード、受け取れる期間、受け取れる枚数、
受け取った人が手にするクーポンを決める。

## 主体と所有

**管理者の役割を要する。** 画面に辿り着けるかは外枠が決めるが、**送信の口も自分で確かめる**。送信は画面とは別の
エントリポイントで、画面を通らずに呼べる。

**業務上の妥当性はバックエンドが持つ。** この画面が見るのは形と、画面から見える前後関係だけである —— コードが
契約の許す綴りか、日時が順に並んでいるか、1 人あたりの上限が総枚数を超えていないか。コードが既に使われているか、
定義が全体として受け付けられるかはバックエンドが判定する（[0070](../../../../../adr/0070-backend-role-separation.md)）。

**定義しただけでは何も配られない。** コードで誰かが受け取るまでクーポンは存在せず、受け取った人が手にするものは
その時点で決まる。定義は後から直せず、一覧から配布を止められるだけである。

## 送るもの

| 項目 | 必須 | 補足 |
| --- | --- | --- |
| キャンペーンコード | ○ | 前後の空白を除き、英字を大文字に揃えてから保存される。許される綴りは契約が持つ |
| 値引き | ○ | 種類（定額か定率か）とその値。上限は定率にだけ付く |
| 範囲 | ○ | 全商品、1 つのカテゴリ、1 つの商品のいずれか |
| 配布開始 / 配布終了 | ○ | 終了は含まない。終了の時刻ちょうどからはコードが使えない |
| クーポンの有効期限 | ○ | 配布終了より後 |
| クーポンの利用開始 | — | 空なら受け取った時点から使える。有効期限より前 |
| 総枚数の上限 / 1 人あたりの上限 | ○ | 1 以上の整数。1 人あたりは総枚数を超えない |
| 最低購入額 | — | 空なら購入額を問わない |

**額は数値を経由させない。** 定額の値引き、上限、最低購入額はドルで、率は百分率で打つ。それぞれ打たれた綴りから契約の
形（decimal 文字列、またはセントの整数）へ写すので、送る前に丸めが入らない。定額は小数第 2 位までで打つ。

**日時は打つ人の時間帯で打ち、瞬間として送る。** 画面が送る直前にその時間帯で壁時計の値を確定させ、受け取る側は同じ
瞬間として読み戻す。

**範囲の対象はちょうど 1 つ。** 全商品は対象を持たず、カテゴリと商品はその識別子を持つ。対象の無い種別は送れない。

## 入力の判定は 1 か所が持つ

**送る前と受け取った後で、同じ module の同じ判定を通す。** 両側にコピーすると、同じ誤りの言い方が 2 つになる。

## 送信

**定義は確認からだけ送る。** 後から変えられず、同じコードは二度と使えないので、出ていく前に内容を一度読み上げる。

**結果が分かるまで、再送は同じ冪等キーを載せる。** 契約はキーを要求し、定義済みのコードを 2 度目に送ると競合になって
初回の結果へ辿れない —— そのため再送が初回の繰り返しかどうかはキーが決める。**失敗が結果を定めないまま残している
あいだ（通信が切れた、サービスが利用できない）は内容を変えられず**、そのまま送り直すことだけができる。同じキーで別の
内容を送ると拒まれるためである。応答が結果を定めたら、次の送信は新しいキーを載せる。開き直した画面は新しいキーを載せる。

**そうした再送に返った競合は、使用済みのコードとして読まない。** バックエンドは、同じキーの送信がまだ処理中のときも
同じ競合を返すため、最初の送信が通っている場合がある。キーと止めた内容は保ち、文言はどちらの場合もありうると言う。
キーを初めて載せた送信に返った競合は、使用済みのコードに限られる。

## 成立したら一覧へ送る

**成立したら一覧を取り直させてから、一覧へ送る。** 一覧は、定義したばかりのキャンペーンが無い状態を見せない。

## 失敗

| 起きたこと | 出すもの |
| --- | --- |
| 形や前後関係の誤り | 欄ごとの文言。送る前に出す |
| コードが既に使われている（キーを初めて載せた送信への競合） | コードの欄に出す。ほかの欄は残す |
| 結果が定まらないあいだの再送への競合 | 確認の中に、使用済みのコードとも処理中の送信とも読める文言で出す。内容は止めたまま |
| バックエンドが欄を名指した | その欄に出す |
| バックエンドが欄を名指さずに内容を拒んだ | 全体の文言を 1 つ、確認の中に出す |
| 結果が定まらない（通信が切れた、サービスが利用できない） | 確認の中に出す。送り直すまで内容を止める |
| 役割が足りない | 送信そのものが通らなかったことだけ |

**欄を名指す拒否は確認を閉じる。** 直す欄は確認の中ではなく画面にある。
