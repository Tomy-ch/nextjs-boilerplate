# `/admin/users/[id]/coupons/new` 1 人のユーザーへのクーポンの発行（画面要件）

> 機能要件は [`page.function.md`](page.function.ja.md)。

受け取り手、次に 1 枚のフォーム。送る前に確認で読み上げる。

## 何を見せるか

**最初に受け取り手を、選ぶものではなく読むものとして出す** —— 名前とメールアドレスに、受け取り手はここでは変えられない
ことと、別の人に発行するにはどこへ行けばよいかを言う 1 行を添える。

**その下に 1 枚のフォームを、上から順に:** 値引き、範囲、有効期限、利用開始日、最低購入額。**デフォルト値を置かない。**
値引きと範囲の欄は、キャンペーンの定義画面と同じに振る舞う
（[`../../../../campaigns/new/page.screen.md`](../../../../campaigns/new/page.screen.ja.md)）。

**退会済みのアカウントにはフォームを出さない** —— 受け取り手と、退会済みのアカウントにはクーポンを発行できないという
素直な一文と、一覧へ戻る道だけを出す。

## 誤りの出し方

**誤りは欄に触れた後にだけ出し、確認を開く操作で残りをすべて出す。**

**有効期限と同時かそれより後の利用開始日は送る前に出す。** 利用開始日の欄に出す。判定するのは引き続きバックエンドである。

**欄を変えたら、前の結果を消す。**

## 確認

**確認は受け取り手を名指し、発行は取り消すことも、無効にすることも、変えることもできないと言う。** すべての値を言葉で
読み上げ、空の任意項目はそれが意味すること（「発行した時点から」/「なし」）で出す。

**欄を指さない失敗は確認の中に出す。** 送る操作の隣に出す。

**送信の結果が定まらないあいだは、フォームを止める。** フォームの上の 1 行が理由を言い ——「前回の発行の結果が分かるまで、
内容は変えられません。同じ内容でもう一度発行してください。」—— 欄は変えられない。

## 成立した後

**フォームは報告に場所を譲る** ——「<name> さんにクーポンを 1 枚発行しました」と内容の読み上げ。確認が閉じても残り、
読み込み直すと消えることを言い、「続けて発行する」と一覧へ戻る道を出す。

**送信時に受け取り手が失われていたら**、フォームは退会済みのアカウントと同じ面に場所を譲る。文言は失敗として言い、
戻る道だけを出す。

## ローディング表示

**受け取り手とカテゴリの選択肢が揃うまで、画面の形をした枠だけを出す。**

## レスポンシブレイアウト

**組になる欄は、広いバンドでは横に並べ、狭いバンドでは縦に積む。**

## 離れるとき

**打ちかけのまま画面を離れようとしたら確認する。** フォームが報告や退会済みのアカウントの面に差し替わっているときは
確認しない。ブラウザの戻る・進むは止めない
（[`navigation-guard`](../../../../../../../../src/components/app-starter/navigation-guard/README.ja.md)）。

## パンくず

**利用者一覧 > <name> > クーポンの発行**（ユーザー一覧 > 受け取り手 > クーポンの発行）。受け取り手が読めないときは、
経路ごと失敗させず、名前を除く。

## カタログでの確認

Storybook の `Page/Admin/Users/CouponNew` が、空と入力済みのフォーム、欄の誤り、有効期限より後の利用開始、確認、送信中、
成立の報告、退会済みのアカウント、送信時に失われた受け取り手または範囲の対象、名指された欄、欄を名指さない拒否、結果が
定まらないあいだ止めたフォーム、競合を、デスクトップ・タブレット・スマホで持つ。コンポーネントは
`Features/Admin/Users/CouponNew` の下に、値引きと範囲の入力は `Features/Admin/CouponDiscountFields` と
`Features/Admin/CouponScopeFields` の下にある。
