# `(shop)` 外枠（機能要件）

> 画面要件は [`layout.screen.md`](layout.screen.ja.md)。
>
> ここに書くのは**配下のすべての画面に効く約束**です。個々の画面はそれぞれの `page.*.md` が持ちます。

## カートの供給

外枠がカートを取得し、header のエントリポイントとサイドバーへ渡す。

**画面ごとに取得しない。** どの画面から商品をカートへ入れても同じ場所に結果が出る必要があり、
画面側に置くと入れられる画面の数だけ取得とコンテナが増える（[0026](../../../adr/0026-layout-shell-mount.ja.md)）。

取得エンドポイントは `/cart` と同じで、同じレンダリングのうちなら往復は 1 回になる。したがって**外枠と本文が別々の
時点のカートを見せることはない**。

**この取得は cookie を読むので、レイアウトシェルのシェルの外に置く。** header のエントリポイントとサイドバーは、それぞれシェルから
切り離したダイナミックホールとして後から届く。レイアウトシェルのシェル（header・nav・footer）と本文のシェルは主体を知らないまま先に
配られ、カートはその後に埋まる（[0041](../../../adr/0041-cache-components-decision.ja.md)）。レイアウトシェルが
取得を抱えると、配下のすべての画面がその往復を待ってからレンダリングし始めることになる。

**取得を持たない案内の 3 枚は、このレイアウトシェルの外に置く。** このレイアウトシェルを通すと、シェルは先に配られても、ダイナミックホールを
埋めるためにリクエストのたびにサーバーが動く。3 枚を build 時の姿だけで配るには、レイアウトシェルがカートも session
も読まないところまで下がるしかなく、
[`../site-info/layout.function.md`](../site-info/layout.function.ja.md) が引き取っている。

**読めなかったときはカートを出さずに続ける。** ここで投げると、同じ段の layout を包む `error`
境界が無いため（子の `error.tsx` は親 layout の失敗を捕まえない）、header も nav も消えた画面まで
落ちる（[0080](../../../adr/0080-error-handling.ja.md)）。カートが読めない状況ではカートの画面自体も
開けないので、外枠からエントリポイントを落としても到達できる場所は減らない。

**空のカートとしては出さない。** 「空」と「読めなかった」は別の状態で、混ぜるとカートが勝手に
空になったように見える。

## 取り消しの記憶

削除した明細を戻すための記憶を、**カートのコンテナより外**に置く。最後の 1 件を取り除くとサイドバーも
カートの画面も空の姿へ変わるため、コンテナの内側に持つとその切り替わりで記憶ごと失われる。

記憶の中身と戻し方は [`cart/page.function.md`](cart/page.function.ja.md) が持つ。

**このレイアウトシェルを離れると失われる。** 案内の 3 枚（[`../site-info/`](../site-info/layout.function.ja.md)）へ
移るとレイアウトシェルごと入れ替わり、記憶は残らない。買い物の内側でだけ意味を持つ便宜なので、買い物から出た
時点で失ってよいものとして扱う（[0026](../../../adr/0026-layout-shell-mount.ja.md)）。跨いでも残す
必要が出たときは、2 つを親の route group でまとめる。

## 認証

**外枠は保護しない。** 商品を見る・カートに入れる・カートを確かめるまでは認証を要さない。保護が
要る画面は、その画面自身が確定認可を行う（[0079](../../../adr/0079-auth-frontend-seam.ja.md)）。

## 行き先

global nav が指すのは商品・購入履歴・マイページの 3 つ。カートは nav ではなく header のエントリポイントが
指す（エントリポイントが中身の開閉を兼ねるため）。

**管理の役割を持つ主体には、管理画面へのエントリポイントを 4 つ目として足す。** 出す・出さないの判定は管理側の
確定認可と同じ述語を使う。判定が別々に書かれていると「入れないのにエントリポイントが出ている」状態を作れて
しまう（[`../admin/layout.function.md`](../admin/layout.function.ja.md)）。

**この判定は session を読む。** 外枠は認証を要さないが、エントリポイントを出すかどうかを決めるために身元は
読む。読めなくても外枠は落とさず、エントリポイントを出さないだけになる。
