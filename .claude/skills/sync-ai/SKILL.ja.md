# Sync AI

スキルを生のディレクトリコピーではなく、**片方向の意味的移植**として同期する。送信元スキルが canonical なのはこの実行の間だけで、受信側スキルは自分の AI 環境にネイティブな形を保つ。**どちらの側も相手のスキルディレクトリを書かない** —— 受信側を迂回した移植は、正しい場所に誤ったイディオムのファイルを置く。それこそがこのスキルが防ごうとしている失敗である。

## 利用シーン

- `.claude/skills/<name>/` のスキルを新規作成した、または大きく変更した。Claude 専用ではない —— Codex へ移植する。
- `.agents/skills/<name>/` のスキルが変わり、Claude 側を追従させたい —— Claude へ移植する。
- Claude と Codex の間で 1 つのスキルを同期・移行・移植・比較するよう頼まれた。

## このスキルを使わないケース

- **EN / JA の対訳ペア** —— `SKILL.md` ↔ `SKILL.ja.md` は `canonicalize-doc` が持つ。
- **実装コードやドキュメントの同期。**
- **双方向の自動マージ、タイムスタンプによる競合解決、ディレクトリの全上書き。** 両方のコピーが変わっていたら、どちらを canonical とするかは人が選ぶ。
- **`codex` の導入。** 使えない CLI は報告すべき所見である（`AGENTS.md` の *Installing Things*）。

## このスキルが届かない範囲

該当するものは毎回の報告で述べる。覆い隠さない。

- **Codex からは実行を始められない。** ここに在る handoff は Claude → Codex（`scripts/sync-ai/`）だけである。Codex 側の `sync-ai` も、Claude を非対話で起動する handoff も存在しないため、Codex → Claude の向きは、Codex 側のコピーを送信元として読む Claude のセッションからしか走らない。
- **Codex の受信側が自分の作成手順を持たないことがある。** スクリプトは `.agents/skills/manage-skill/SKILL.md` の有無を確かめ、在ればそれを使うよう、無ければ Codex ネイティブのスキル形式で直接書いてその旨を報告に残すよう Codex に告げる。<!-- skill-lint-ignore --> 後者の場合、受信側の規約検査は走っていない。報告にそう書く。
- **`codex` は、このリポジトリが走らせるどの手順も導入しない。** `PATH` に無ければスクリプトは 4 で終わり、実行はその所見を持って止まる。

## Step 0. 向きと単位を確定する

スキル名 1 つと向き 1 つを `AskUserQuestion` で確定する。`$ARGUMENTS` の値は黙って採らず、推奨の選択肢として出す。

```text
source: .claude/skills/<name>/  → target: .agents/skills/<name>/
source: .agents/skills/<name>/  → target: .claude/skills/<name>/
```

向きをファイルの mtime から推定しない。前回一致して以降に両方のコピーが変わっていたら、止まってどちらが canonical かを尋ねる。

送信元の単位全体と、在れば受信側の単位を読む。`SKILL.md`、`SKILL.ja.md`、UI メタデータ、`scripts/`、`references/`、`prompts/`、`assets/` を 1 単位として扱う。スキルディレクトリの内側ではなくリポジトリの `scripts/<tool>/` にスクリプトを持つスキルは、そのスクリプトも単位の一部として契約で名指す。

## Step 1. 転送契約を作る

目的、起動・非起動の条件、入力、承認、副作用、検証、再利用する資産を抽出する。各項目を **port**、**adapt**、**omit** に分類する。プラットフォームの機構はコピーせず変換する。Claude の `AskUserQuestion` / `Agent` / `Skill` の指示と frontmatter の `allowed-tools` をそのまま Codex へ渡してはならず、Codex の delegation やツール指示も Claude の構文にしてはならない。

契約は `tmp/skills/sync-ai/<name>-contract.md` へ書く —— このスキルが書く唯一のファイルである。永続的な第 3 のコピーや同期 manifest は作らない。

Codex が受信側のとき、契約は何も尋ねられない**非対話**の受信側へ渡る。したがって完全性は上品さの問題ではない。受信側が尋ねたくなる問いはすべて、契約の中で決着させるか、受信側の判断に委ねると明記する。曖昧さは引き渡しの前に、こちら側でユーザーと解消する。受信側がそれを知る手順を持たないことがあるので、受信側が従うべき規約（言語、frontmatter のキー、ファイル配置）を契約に書く。

## Step 2. 契約を受信側へ渡す

**Claude が受信側**（`.claude/skills/<name>/`）の場合は、契約を渡して `/manage-skill` を起動する。受信側をその場で作成・更新し、このリポジトリの frontmatter と本文の規則を当て、`SKILL.ja.md` を同期する。

**Codex が受信側**（`.agents/skills/<name>/`）の場合は、Codex を起動する前に `AskUserQuestion` で確認する —— 作業ツリーへ書き込む、別の有料エージェントを走らせるためである。そのうえで次を実行する。

```sh
pnpm exec tsx scripts/sync-ai tmp/skills/sync-ai/<name>-contract.md
```

スクリプトは起動の姿勢を 1 箇所に置く。`codex exec --sandbox workspace-write` に、書き込み可能な root として `.agents/` を足し、プロンプトは標準入力から渡し、子操作としての前置きを付ける —— 質問しない、別のエージェントを起動しない、書き込みは `.agents/skills/<name>/` と `tmp/` に限る。フラグを変える前に `scripts/sync-ai/handoff.ts` を読む。

**再帰の上限を与えるのは前置きではなくリースである。** スクリプトは Codex を起動する前に `tmp/skills/sync-ai/.handoff.lock` を取り、既に保持されていれば拒否する。よって再び handoff しようとした受信側は、連鎖を深めるのではなく追い返される。指示は無視され得るし、無視した連鎖は両方のエージェントに費用を払わせながら回り続ける。

| 終了コード | 意味 | すること |
| --- | --- | --- |
| 0 | Codex が終わった | Step 3 へ進む |
| 2 | 契約のパスが無い、または契約を読めない | パスを直す |
| 3 | リースが保持されている | 連鎖が再帰しようとした（ガードが働いた）か、前回の実行が kill された —— どちらを確かめるかはメッセージが述べ、消すべきパスを表示する |
| 4 | `codex` が `PATH` に無い | 止まって所見として報告する。導入しない |
| その他 | Codex 自身の終了ステータス | Codex が出力したものと併せて報告する |

送信元スキルを削除しない。commit、push、公開、他のスキルの変更をしない。

## Step 3. 検証と報告

受信側の要約は主張であって証拠ではない。対象ディレクトリの `git status` と `git diff` を読み、そこから判断する。**何も書かずに成功を報告する handoff が、最初に疑うべき失敗である。**

- 受信側が、受信側の環境で使える機構だけを使いながら、送信元の振る舞いを保っていることを確かめる。
- diff に出ないものを確かめる。新しく同梱されたスクリプトの実行ビット（`ls -l`）と、Claude が受信側なら `SKILL.md` と `SKILL.ja.md` の見出し構造の一致。
- 受信側が逆向きの同期を求めてきても、**この実行の中で始めない。** 先にユーザーへ確認する。実行が自分で始める折り返しは、内側から見ればループの 1 周目と区別がつかない。このゲートが在り得るのは連鎖の最上位だけで、それより下のプロセスはすべて非対話である —— だから再帰を抑えるのはこのゲートではなくリースである。

報告は日本語で書く。向き、送信元の commit または差分の基準、port / adapt / omit の判断、変更したファイル、受信側で表現できない意図、そして *このスキルが届かない範囲* のうちこの実行に当てはまったものすべて。

## AI Modification Scope

このスキル自身が書くのは `tmp/skills/sync-ai/` だけである。対象スキルのディレクトリへの書き込みは受信側が行う —— `/manage-skill` は自身が宣言する範囲で、Codex は前置きが名指すパスで。`AGENTS.md`、Accepted な ADR の本文、`LICENSE`、`permissions.deny` 配下のものは、終始保護されたままである。

## ガードレール

- 同期を始めた実行が連鎖の最上位である。受信側は子操作であり、2 回目の外向きの同期を始めてはならない。
- 非対話の受信側にユーザーはいない。質問されることを前提にした契約を渡さず、誰も与えられない承認を待てるようなフラグも渡さない。
- 特定のプラットフォーム専用のスキルは専用のままにし、理由を報告する。
- 転送の成果物は gitignore された `tmp/` に置く。保守するコピーは 2 つのネイティブなスキルディレクトリだけである。
